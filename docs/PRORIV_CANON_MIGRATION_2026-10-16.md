## Требуемое согласование интерактивных экранов и данных
- [ ] **Карта ролей:** администратор управляет созданием/закрытием объектов, планом работ, назначениями и просмотром чужих объектов другими прорабами; работник видит лишь разрешённые данные, не цены.
- [ ] **Общий процесс:** автоматическое создание/закрытие связанного Tripletex Project, итоговый рапорт прораба до закрытия, новый объект при новых работах.
- [ ] **Учёт часов:** Start, Pause, Stop; смена 07:00 по умолчанию; напоминание перед началом; персональные часы.
- [ ] **Геолокация:** GPS и дистанция на Start/Stop, **без блокировки по расстоянию**, без геозон, без геоограничений для Pause.
- [ ] **Ручные исправления:** причина, жёлтая отметка до проверки, зелёная после; прораб вправе подтверждать собственные исправленные часы.
- [ ] **Работы/фото:** выбор вида работы из каталога, количество и фотографии; свободное описание работ не обязательно.
- [ ] **Рапорты:** каждый работник создаёт свой, когда нужно; отправка напрямую или через прораба; через прораба можно объединить индивидуальные рапорты в один общий для клиента.
- [ ] **Клиентские данные:** в клиентском рапорте нет имён исполнителей и их часов; это касается также объединённого рапорта.
- [ ] **Стоимость/скидки:** работнику цены не видны, прораб и админ могут указывать скидки; админ видит автора и сумму.
- [ ] **Уведомления:** при отсутствии ответа со следующего дня ежедневное напоминание с настраиваемым расписанием на уровне клиента; нет автоматического одобрения.
- [ ] **Клиентская реакция:** ответ по e-mail; привязка к объекту/рапорту; уведомление всех с доступом; Jev: ожидание, принято, отказ, нужно уточнить (последнее проверяет прораб).
- [ ] **Tripletex:** рабочие часы утверждаются прорабом в ProRiv; проверка клиентом независима; передаются новые утверждённые часы и проверенные рапорты, без повторной отправки тех же часов; технический формат подтвердить.
- [ ] **История:** автор, время, содержание изменений рапорта, события отправки и реакции клиента.
- [ ] **Аналитика:** выручка, принесённая работами каждого сотрудника (не зарплата); расчёт для совместной работы ещё открыть.
- [ ] **Offline:** отдельный тест локальной записи времени, фотографий, рапортов и последующей синхронизации; не считать доказанным.
- [ ] **HMS:** убрать как обязательный процесс текущего объёма; исторические вопросы оставить как архив.
- [ ] **Внедрение:** Dev → Release (проверка клиентом) → Production.
